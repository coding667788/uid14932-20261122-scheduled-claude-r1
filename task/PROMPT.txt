我们需要给几个互不完全信任的站点发同一份内部通报。网络团队能提前配置两棵独立的组播树，但一部分中转站只能接触密文。请交付一个离线布置与审核工具，所有站点、消息、链路和信任证据均为合成输入，只模拟两种封装标签，不接实际网络或密钥。

每个消息从一个已登记的发布站出发，有主题、密级、世代和截止时间。树中的每条有向边同时约束可走密级和整数链路延迟闭区间。节点可原样转发密文。改变明密文形态需要输入授权，且只能在指定节点执行。节点能够看到明文时，不论它是否是指定接收者，都必须在该主题的明文许可集合中。不得把入站已经是明文的中转当成「没有显式解封所以不可见」。允许分支出口采用不同封装，但每份复制出来的消息都继承同一输入摘要、主题和世代，且各自的转换须有独立许可。未列出的站点不可成为叶节点。中转授权、故障域配置和发布接受窗口按同一份输入版本核对，不可拼接。

plan 从获批边、节点和转换中选择两棵有根树及每条分支的封装。两树都必须达到所有接收站。任意一个共享故障域失效时，有时不同接收者只能分别用不同的树。要求每个接收者至少一条实际存活路径可按期送达，不能仅比较两树的整体域集合。故障情形为无故障或任一域在整次传送期间失效，域可包含边和中转节点。对每个允许的发布时间和链路延迟逐项核验。输入提供前一版本的双树与目录，plan 只布置新版本，还要核查两个发布接受窗口交叠时的迟到分支。旧消息始终沿旧树和旧封装传播，旧节点一旦不再有明文许可，路径必须在到达该节点前明确丢弃，不能利用新接收者名单提前确认旧消息。同版本同摘要的两路送达只生成一条接收回执。成本先计两棵树启用的不同边总费，再计全部转换次数和最坏送达耗时。仍并列时按两树的规范边及转换序列决胜，无主备先后要求时将较小树放在前面。支持 18 个候选节点、32 条边、7 个接收者和 6 个故障域。

check 给出拓扑、发布时刻及故障域的可复算验证，报告最先越权的中转点或最先失去的接收者及路径。对未发现可行双树的输入，验证指定基线并提供可重演的失败见证。用独立小图枚举核对可行性和成本。验收至少覆盖两棵树各自可达却共享同一关键域、两树均中断但每个接收者仍各有一条完好分支、便宜边复用破坏容灾、受禁明文的中转、旧世代到达时已撤授权、以及恰在截止时刻到达。输入明确事件同刻顺序为先处理策略再处理到达，截止点允许到达。

程序运行在 Windows 原生 Python 3.12 上，使用标准库和 CPU。请从空仓库实现 python -m multicast_guard <命令> CASE.json，命令产生可复现的 UTF-8 JSON，格式错误报告字段路径。交付能直接复验的虚构案例、定义完整输入输出及复验命令的 README，还有 unittest 可执行的断言测试。
